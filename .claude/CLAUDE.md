## Writing

Apply the `core:technical-english` skill to documentation, code
comments, and responses.

## Principles

Apply each `core:*-principles` skill whenever its description matches the
work.

## Responses

Keep responses focused and brief. Lead with the answer, then add only the
detail I need to act on it. Skip recaps, caveats, and options you won't
pursue. When I ask you to explain something, give a high-level summary
unless I ask for depth.

## Questions

When I ask a question ("why", "how", "what"), answer it and stop. Do not
edit files, run state-changing commands, or offer a diff. Reading files
to answer is fine. If you can't tell whether I'm asking or requesting,
treat it as a question.

## Current state and history

Always use Git for history. Files at HEAD must describe one current
state. When something changes, update or replace it in place and keep
affected code, documentation, and references consistent. Do not retain
superseded versions, retired requirements, or embedded change histories
alongside the current state.
